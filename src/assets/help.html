WebSocket2Serial 是本机常驻的 WebSocket ↔ 串口透传服务。本页汇总页面入口、串口参数、 占用规则和完整的通信协议。

快速开始
  1. 在管理页「串口」表确认当前机器识别到的串口。
  2. 点「串口助手」或端口行的「用助手打开」，在新标签选择参数并打开串口。
  3. 在助手页发送文本或 HEX，接收区查看设备返回；需要协议/边界验证时打开「功能测试」。
  4. 调试结束后点「关闭串口」立即释放端口，再关闭标签页。
三个页面分别做什么
  • 管理页：服务状态、串口列表、会话监控、帮助入口。
  • 串口助手：自己打开/关闭一个串口，做日常人工收发与调试；多个串口请开多个标签页。
  • 功能测试：协议动作、事件、错误码、宽限重连与一键完整演示。
串口参数

波特率、数据位、校验、停止位、流控和 DTR/RTS 必须与设备一致。不确定时先用 115200 8N1、无流控。

  • 数据位：5–8；v1 校验仅支持 none / odd / even。
  • 流控：none / software / hardware。
  • DTR/RTS 可留默认，打开时再施加指定电平。
串口占用与宽限

同一串口同时只允许一个数据客户端。若助手页提示 PORT_BUSY，请先在管理页「会话」表关闭占用会话， 或关闭其他串口程序。直接关闭助手标签页不会立刻释放串口，会进入 10 秒宽限；建议先点「关闭串口」。

通信协议（ws2s/v1）

协议固定使用 127.0.0.1，不使用 localhost。管理 WS 只做浏览器 Origin 白名单校验； 数据 WS 仅靠 URL 中的随机 token 识别。数据面是流式透传，不保证报文边界。

1. 两类连接

连接地址用途
管理 WebSocketws://127.0.0.1:8765/ws枚举串口、打开/关闭会话、调试订阅、状态事件
数据 WebSocketws://127.0.0.1:<dataPort>/ws/<token>串口字节二进制原样透传；每个会话一个

2. 消息封装

请求（客户端 → 管理 WS）：

{ "id": "任意字符串", "action": "动作名", "params": { } }

成功应答：

{ "id": "...", "ok": true, "data": { } }

失败应答：

{ "id": "...", "ok": false, "error": { "code": "PORT_BUSY", "message": "串口被占用", "detail": { } } }

事件（不带 id）：

{ "event": "hello", "data": { } }

客户端按「有无 id」区分应答与事件，并按 id 关联请求。

SessionInfo（session.list）

主要字段：sessionId、state（awaiting / active / grace / closed）、port、 params、createdAt、dataPort、connectBy、activeSince、 graceEndsAt、counters、lastGap、lastError、lastRxAt、lastTxAt。

lastGap：startedAt、durationMs、discardedBytes、resumed。

session.write 与 debug.subscribe

  • session.write：base64 原始字节，单次 ≤ 64 KiB；仅 active 会话可用，仅用于排障，可能造成字节交错。
  • debug.subscribe：replay: true 先回放 64 KiB 环形缓冲，再收实时帧；调试帧可丢弃，seq 可见缺口。
  • admin.set：运行时开关管理页服务，不回写配置；成功后广播 admin.state。

管理协议错误码（error.code）

错误码含义
INVALID_REQUESTJSON 格式或请求结构错误
UNKNOWN_ACTION未知 action
INVALID_PARAMS参数缺失或取值非法

LIMIT_EXCEEDED超过最大会话数或队列上限

数据 WS close code

代码含义
1000客户端正常关闭，服务端按 CLIENT_CLOSED 释放串口
1001服务端退出/心跳判死等正常性离开
1003收到文本帧（数据面只接受二进制）
1009单帧超过上限（默认 1 MiB）
4001串口设备消失（DEVICE_LOST）
4002端口被占用 / 会话已 active，第二客户端被拒
4004管理端关闭（ADMIN_CLOSED）
4005接收背压（BACKPRESSURE）
4007串口读写错误 / 写停滞超时（SERIAL_IO_ERROR / WRITE_TIMEOUT）

管理 WS close code

代码含义
1000客户端主动关闭的回显
1001心跳判死（10s 无 Pong）或离开
1013写队列满 / 广播落后，服务端强制断开（客户端应重连 + session.list 对齐）

会话关闭原因以数据 WS 的 close code 为准，不要依赖管理事件与数据帧的到达顺序。

6. 复用、token 与重连

  • 同端口已有 awaiting / grace 会话：session.open 返回原会话（reused=true），轮换 token 和 dataUrl，旧 URL 立即失效。
  • 同端口已有 active 会话：返回 PORT_BUSY；每端口同时只有一个活跃数据连接。
  • token 为 128 位随机值十六进制串，仅随 session.open 返回，不出现在 session.list。
  • 页面刷新/重启后直接再次 session.open（带相同参数）即可接回；不需要保存 sessionId/token。
  • 数据 WS 断开时先在宽限期内重连原 dataUrl；失败后 session.open 复用并轮换 token，按 200–500ms 起步退避。
  • 管理 WS 重连后先 session.list 对齐状态，再恢复 debug.subscribe；CSP 需允许 ws://127.0.0.1:*。
与浏览器 Web Serial 的区别

本工具通过本机 WebSocket2Serial 透传服务访问串口，不需要浏览器 Web Serial 授权弹窗； 因此页面必须从 http://127.0.0.1:8766 打开，且串口仍受“同一串口一个数据客户端”的限制。

管理服务关闭后怎么恢复

管理页关闭只影响 8766 的 HTTP 页面，不影响管理 WS 与已打开的数据 WS。可从托盘菜单重新开启，或用 --admin 启动参数强制开启。
