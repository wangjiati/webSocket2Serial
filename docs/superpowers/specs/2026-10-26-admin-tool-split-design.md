# 管理工具拆分为三个页面设计

- 日期：2026-10-26
- 状态：已批准（2026-10-26）
- 相关实现：`src/assets/*`、`src/http/mod.rs`、`tests/admin_assets.rs`

## 1. 背景与意图

当前管理页把「概览」「串口助手」「功能演示」塞在同一个页面里：概览做状态监控，串口助手只是被动查看调试帧，功能演示是最近并入的 7 个测试子 tab。三者定位不同，混在一起后管理页越来越重，串口助手也不像现场调试人员熟悉的串口工具。

现场的主要使用方式是：日常人工调试、临时发指令、看设备日志、做协议联调。需要把工具拆成三个独立页面：

1. **管理页**：状态监控、串口/会话总览、帮助文档。
2. **串口助手**：真正可用的串口调试工具，自己选择并打开/关闭串口。
3. **功能测试**：保留现有 7 个子 tab 的协议演示与一键自检。

三个页面都由本机管理 HTTP 服务提供；管理页用新标签页打开另外两个页面。

## 2. 调研结论：串口助手常见能力

调研对象：SSCOM、UartAssist/XCOM、RealTerm、CoolTerm、AetherPort、Web Serial Debug、波特律动、聆思在线终端。

共性能力：

- **连接参数**：端口扫描、波特率（含自定义）、数据位/校验/停止位、软硬件流控、DTR/RTS、打开/关闭、引脚状态。
- **收发显示**：文本/HEX、编码（UTF-8/GBK/ANSI）、时间戳、暂停/清空/自动滚动、换行符、接收缓冲、字节与速率统计。
- **发送增强**：快捷指令、发送历史、定时/循环发送、多指令序列、文件导入、转义字符、AT 自动 CRLF、校验和（Sum/XOR/CRC16）。
- **日志**：TXT/CSV 导出、原始数据保存、按时间/大小分文件、日志级别高亮。
- **高级能力**：协议解析、波形绘制、自动应答/脚本、XMODEM/YMODEM/ZMODEM、多串口同屏。

在线 Web Serial 工具依赖 Chrome/Edge 的 Web Serial API 和用户手势授权；本工具通过本机透传服务走 WebSocket，不需要授权弹窗，但**同一串口同时只能有一个数据客户端**，这是三个页面之间必须显式说明的约束。

## 3. 目标

1. 管理页只做状态监控与帮助，不再承载串口助手和功能测试。
2. 串口助手自己选择串口、配置参数、打开/关闭会话，并通过数据 WS 完成日常人工收发调试。
3. 功能测试页保留现有 7 个子 tab、边界自检与一键演示。
4. 管理页用新标签页打开串口助手和功能测试；助手/测试页提供返回管理页的入口。
5. 串口助手顶部有醒目提示：通过透传工具访问、不是 Web Serial、同一串口只能一个数据客户端、被占用时如何释放。
6. 三个页面继续零构建、无 CDN、无外部字体，兼容 Chrome 109 / Firefox 115 ESR。

## 4. 非目标

- 不做 Web Serial API、不申请浏览器串口权限。
- 不做协议解析、波形绘制、自动应答、脚本、XMODEM/YMODEM/ZMODEM、文件发送（首版）。
- 不做单页多串口同屏；多串口通过打开多个助手标签页实现。
- 不新增或修改管理协议动作/事件；继续使用 7 个动作、5 个事件。
- 不做管理鉴权、跨网络访问、HTTPS。
- 不把串口数据写盘；导出仅由用户手动触发。
- 不保留旧的管理页内「串口助手」监控面板。

## 5. 反目标

- 串口助手仍然只是被动看 `debug.frame`，无法自己打开串口或发送数据。
- 助手和功能测试页同时打开同一个串口却没有明确错误提示。
- 三个页面互相复制整套数据 WS/管理 WS 逻辑，后续修一处漏两处。
- 管理页继续把三个功能堆在 tab 里，页面越来越重。
- 关闭管理服务后，已经打开的助手/测试页立即失效；管理服务只影响 HTTP 页面，不影响管理 WS 与数据 WS。

## 6. 已确认的决策

| 项 | 决定 | 来源 |
|---|---|---|
| 页面数量 | 三个独立页面，管理页新标签打开另外两个 | 用户 |
| 串口助手定位 | 自己选择/打开/关闭串口，日常人工调试 | 用户 |
| 管理页定位 | 状态监控、会话、帮助文档 | 用户 |
| 功能测试 | 复用现有 7 子 tab 演示 | 建造者（用户未反对） |
| 首版助手范围 | 连接参数、收发、HEX/文本、时间戳、暂停/清空/导出、快捷指令、定时/循环、校验和、统计 | 用户确认范围 |
| 多串口 | 一个助手页一个串口，多开标签页 | 建造者 |
| 文本编码 | 接收 UTF-8/GBK，发送 UTF-8；GBK/二进制发送用 HEX | 建造者 |
| 关闭页面 | 沿用 10 秒宽限；助手提供「关闭串口」立即释放 | 建造者 |
| 帮助文档 | 内置精简 HTML，不依赖仓库外文件 | 建造者 |

## 7. 页面信息架构

### 7.1 路由

| 路径 | 页面 | 说明 |
|---|---|---|
| `/` | 管理页 | 状态监控、串口/会话、帮助 |
| `/assistant` | 串口助手 | 自己打开/关闭串口并收发 |
| `/test` | 功能测试 | 现有 7 子 tab 演示 |

静态资源继续走 `/style.css`、`/js/*`。旧 `/js/assistant.js` 删除。

### 7.2 管理页 `/`

从上到下：

1. 页头：标题、管理 WS 连接状态、`串口助手 ↗`、`功能测试 ↗`（`target="_blank" rel="noopener"`）。
2. 入口卡片：两张，分别说明「日常串口调试」和「协议/边界自检」，点击在新标签打开。
3. 服务状态：版本、管理地址（复制）、管理服务开关（保留确认）、开机自启（只读）。
4. 串口列表：路径、VID/PID、厂商、产品、序列号、类型；每行提供「用助手打开」（`/assistant?port=...`，新标签）。
5. 会话表：会话、状态、串口/参数、RX/TX/DROP、最近断线、最近错误、关闭按钮。
6. 帮助文档：快速开始、三个页面说明、参数解释、串口占用/宽限、错误码、浏览器兼容、与 Web Serial 的区别。

管理页每 2 秒轮询一次 `session.list` 刷新计数；页面隐藏时暂停轮询。

### 7.3 串口助手 `/assistant`

页头：标题、连接/会话状态、`← 返回管理页`、`功能测试 ↗`。

固定提示条（醒目、始终可见）：

> 本页通过 WebSocket2Serial 透传工具访问串口，不是浏览器 Web Serial。同一串口同时只允许一个数据客户端；若提示 PORT_BUSY，请先在管理页关闭占用会话，或关闭其他串口程序。

布局（宽屏两列，窄屏单列）：

- **连接卡片**：串口输入 + datalist、波特率（含自定义）、数据位、校验、停止位、流控、DTR/RTS、打开/关闭按钮、状态徽标、RX/TX/DROP、最近错误。
- **接收日志**（主区域）：时间戳、RX/TX、HEX/ASCII、暂停、清空、自动滚动、导出 TXT、缓冲上限提示。
- **发送卡片**：文本/HEX、行尾（无/CR/LF/CRLF）、发送框、发送按钮、发送历史、校验和（无/Sum8/XOR8/CRC16-Modbus）、定时/循环发送（间隔 ms、次数 0=无限、开始/停止）。
- **快捷指令卡片**：名称 + 内容 + 模式 + 行尾；保存、载入、发送、删除；保存在 `localStorage`。
- **统计卡片**：RX/TX 字节、实时速率、会话状态、最后错误/缺口。

行为：

- 打开：`session.open` → 用返回的 `dataUrl` 建立数据 WS；成功后 active。
- 关闭：`session.close` → 关闭数据 WS → closed；保留日志直到用户清空。
- 数据 WS 异常关闭：显示 close code / grace；提供「重新连接」（复用 `session.open`，宽限期内会复用并轮换 token）和「关闭会话」。
- 管理 WS 断开：收发仍可继续（数据 WS 独立），但打开/关闭/会话状态不可用；页头提示离线。
- `PORT_BUSY`：显示明确错误 + 「打开管理页关闭会话」按钮；不自动重试。
- 页面带 `?port=COM3` 时预填串口，不自动打开。
- 关闭页面：沿用 10 秒宽限；助手页显式提供「关闭串口」按钮。是否在 `beforeunload` 提示由建造者决定。
- 一个助手页只管理一个会话；多串口开多个标签页。

### 7.4 功能测试 `/test`

- 页头：标题、`← 返回管理页`、`串口助手 ↗`（新标签）。
- 保留现有演示状态条、7 个子 tab、全部 ID 与 `createDemo(root, client)` 逻辑。
- 一键演示继续跳过「关闭管理页」；清理只关闭 A/B。
- 样式继续使用 `#demo` 作用域。

## 9. HTTP 与缓存

- 新增 `include_str!`：`ASSISTANT_HTML`、`TEST_HTML`、`JS_FORMAT`、`JS_SERIAL`、`JS_ASSISTANT_PAGE`、`JS_TEST_PAGE`。
- 路由：`/assistant`、`/test`、`/js/*` 增加四个新模块；删除 `assistant.js`。
- 所有 HTML/CSS/JS 响应加 `Cache-Control: no-store`，避免升级 exe 后浏览器继续用旧页面/旧模块。
- `/api/config` 不变。

## 10. 错误处理与边界

- 管理 WS 未连接：管理页显示连接中；助手页打开/关闭按钮禁用，收发区提示离线。
- `PORT_BUSY`：助手页显示“串口已被占用”，给出管理页会话表的关闭指引；不自动重试。
- `PORT_NOT_FOUND`：提示端口不存在，刷新端口列表。
- 数据 WS 关闭码：1000 正常关闭；4002 第二客户端；4004 管理端关闭；4005 接收背压；4007 写停滞；其他进入 grace。
- 缓冲上限：5000 帧 / 4 MiB；超出丢最旧并显示提示。
- 定时/循环发送：关闭串口、数据 WS 断开、页面隐藏（可选）时自动停止。
- 页面关闭：10 秒宽限；助手页应在 UI 中说明。
- 管理页关闭服务：已打开页面继续可用；新标签打开会失败，帮助文档说明如何从托盘/`--admin` 恢复。

3. 快捷指令保存/载入/发送/删除；定时/循环发送可停；Sum8/XOR8/CRC16 附加字节正确。

## 12. 风险与取舍

- **共享代码提取**：从 1700 行 `demo.js` 抽出 `SerialSession`/工具函数，可能回归测试页；靠测试页手工冒烟和现有自动化兜底。
- **串口占用冲突**：三个页面共享物理串口，助手/测试页不能同时用一个口；用醒目提示、`PORT_BUSY` 引导和管理页会话关闭解决。
- **GBK 发送**：浏览器 `TextEncoder` 只支持 UTF-8；首版 GBK 仅接收，发送建议 HEX。若现场必须 GBK 发送，需要额外编码表/库。
- **关闭页面宽限**：直接关标签会占口最多 10 秒；助手页提供关闭按钮并在帮助里说明。
- **帮助文档内置**：内容与仓库 README/协议文档可能漂移；帮助页只放稳定操作说明，详细协议仍指向 `docs/protocol-v1.md`。
- **多标签页**：两个助手标签可以各管一个口；管理页可看到全部会话，但协议没有“属主”字段，无法显示哪个页面拥有会话。

## 13. 建造者自行决定的部分

- 助手页的具体栅格、卡片顺序、日志高度、按钮文案和窄屏断点。
- 快捷指令、发送历史、上次参数的 `localStorage` 键名与清理策略。
- 是否在 `beforeunload` 时提示“串口仍打开”。
- 校验和的展示方式与 CRC16 字节序（默认 Modbus 小端）。
- 共享模块的拆分粒度（`format.js` / `serial.js` 是否再拆）。
- 帮助文档的具体条目与折叠方式。
